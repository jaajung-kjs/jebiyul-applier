# 적용근거 코드 생성 렌더러 — 설계

**작성일:** 2026-06-30
**상태:** 승인 대기(스펙 검토 전)
**선행 설계:** `docs/superpowers/specs/2026-06-30-적용근거-생성기-design.md` (1차 — 템플릿 복사 방식)

## 1. 배경과 문제

1차 구현은 PIU 설계서의 `8.적용근거` 시트를 통째로 추출한 마스터 템플릿
(`assets/template_적용근거.xlsx`)을 **복사**한 뒤 고정 좌표(I14, B7, D47 …)의 값만
덮어쓴다. 결과적으로:

- 입력(공사종류·규모·기간·계약방법)이 달라져도 **표 구조·행 수·셀 위치·색이 한 글자도
  안 바뀌고** 고정 칸의 숫자만 변한다. → 휴리스틱이지 자동 생성이 아니다.
- PIU 양식 자체가 "50억 미만" 기준으로 압축돼 있어(`50억 이상 → 조달청 참조` 한 줄),
  50억 이상 공사는 구조적으로 부정확하다.

## 2. 목표

입력에 따라 **양식 자체를 코드로 그려서 생성**하는 진짜 RPA로 전환한다. PIU
`8.적용근거`와 **시각적으로 동일**하되, 좌표 하드코딩이 아니라 레이아웃 모델을
렌더링하므로 입력에 따라 행이 늘고 줄며 서식이 따라온다.

### 핵심 원칙 (불변)

각 비목은 PIU와 동일하게 **3단 구조**로 "적용 기준과 근거를 설명하고 결과 %를 보여준다":

1. **적용기준** — 무엇에 적용하는지(대상공사·공사규모별 적용기준)
2. **근거** — 계상금액 산식 + 율의 출처(구간표 / 보험요율)
3. **적용율** — 최종 몇 %인지 (구간표의 적용 셀을 참조하는 수식)

이 3단을 명확히 전달하는 것이 산출물의 목적이다. 표·색·병합은 이 설명을 읽기 쉽게
하는 수단이다.

## 3. PIU 동일 ↔ 입력 자동생성 충돌 해결

PIU 양식은 "50억 미만" 4개 기간 행 + "50억 이상 → 참조" 한 줄로 **압축된 50억미만
기준 양식**이다. 두 요구를 동시에 만족시킨다:

- **공사규모 < 50억** → PIU와 픽셀 동일(50억미만 4기간 행 + 참조줄), 해당 기간 행만 강조.
- **공사규모 ≥ 50억** → 참조줄 대신 그 공사의 실제 규모구간(예: 300~1000억) 4기간 행을
  **펼쳐서** 그리고, 해당 셀을 강조.

→ 표 형태가 입력에 따라 바뀌므로(진짜 자동생성), 일반적인 <50억 공사에서는 PIU와 동일.
조달청 토목/건축 제비율 파일에 5규모×4기간 완전 매트릭스가 존재함을 확인했다(데이터 근거).

## 4. 아키텍처

책임을 분리한 3개 신규 모듈 + 기존 모듈 경량 수정.

| 모듈 | 역할 | 의존 |
|---|---|---|
| `src/sheet_model.py` (신규) | `params`+`rates`+제비율 조회 → **블록 리스트** 산출. openpyxl 없음, 순수 데이터. **입력이 구조를 결정하는 유일한 곳** | `lookup`, `params` |
| `src/styles.py` (신규) | PIU에서 추출한 스타일 팔레트(폰트·채움·테두리·정렬·열폭·강조색) | `openpyxl` |
| `src/renderer.py` (신규) | 블록 리스트를 위→아래로 훑으며 **행 커서**를 늘려가며 값·수식·병합·스타일·열폭·행높이 출력 → xlsx | `openpyxl`, `styles` |
| `src/builder.py` (수정) | `build_output()` 시그니처 유지(gui/main 호환). 내부를 `sheet_model.build()` → `renderer.render()`로 교체 | `sheet_model`, `renderer` |
| `lookup`/`params`/`mapping`/`gui`/`main` | 변경 없음(또는 최소) | — |

`assets/template_적용근거.xlsx` 의존 제거. 골든 비교용 참조로만 보관.

### 데이터 흐름

```
params → compute_rates(기존) → sheet_model.build(params, rates, jebiyul_path)
       → [블록 리스트] → renderer.render(blocks, out_path) → xlsx
```

## 5. 레이아웃 모델 (블록 타입)

순수 데이터 구조. 렌더러가 해석한다. 좌표는 갖지 않고 **순서**만 가진다(렌더러가 행
커서로 좌표 부여).

- `Title(text)` — "8. 공사비 산출 적용근거" 시트 제목.
- `SectionHeader(num, text, note?)` — "1. 간접노무비", 우측 [조달청 … 적용] 주석.
- `SubHeader(text)` — "가. 공구손료" 등.
- `NoteLines(lines[])` — ☞ 적용기준/계상금액 설명줄(들여쓰기 보존).
- `BandTable(columns, rows, highlight_idx, applied_ref_label)` — 구간표. 헤더 + 데이터
  행들. `highlight_idx`로 적용 행 강조, `applied_ref_label`로 적용율 참조 대상 셀 지정.
- `AppliedRate(label, ref|value)` — "☞ 적 용 율 : (일반)" + 우측 율 셀(가능하면 표
  셀 참조 수식, 아니면 값).

각 비목 섹션은 위 블록들의 조합으로 표현된다. 입력에 따라 `BandTable.rows`의 개수와
`highlight_idx`가 달라지는 것이 자동 생성의 본질이다.

## 6. 비목별 입력 구동 규칙

- **간접노무비·기타경비**: §3 압축/펼침 규칙. 적용 셀 강조, `AppliedRate`는 강조 셀 참조.
- **산업안전보건관리비**: 4개 대상액 구간(2천만미만/5억미만/5-50억/50억이상), 해당 구간 강조.
  50억이상 800억 한계는 `NoteLines`에 주석.
- **일반관리비**: 4개 규모구간(전문 5/30/100억 스케줄), 해당 구간 강조.
- **이윤**: 경쟁(4 규모) + 수의(2 규모), 계약방법에 따라 해당 행 강조. 일반/수의 적용율을
  각각의 셀로 참조.
- **고정율(산재·고용·건강·연금·퇴직·노인·공구손료)**: `NoteLines`에 율을 박고 `AppliedRate`
  출력. 표 없음.

## 7. 스타일 충실도

PIU `8.적용근거`에서 추출해 `styles.py`에 상수로 고정:

- 열폭: A4.2, B10.2, C14.1, D10.2, E12.6, G10.2, H12.4, I10.2, K2.5.
- 표 헤더: 회색 채움 + 가운데 정렬 + 굵게.
- 표 데이터 셀: 얇은 테두리(thin), 율 셀 백분율/소수 표기.
- 섹션 제목: 굵게.
- ☞ 근거줄: 들여쓰기(선행 공백) 보존, 일반 폰트.
- **강조 채움(신규)**: 적용 행을 옅은 색(예: 연노랑)으로 칠해 "이번 공사 해당" 표시.
- 병합: 블록별 실제 행 위치 기준으로 재계산(고정 좌표 아님).

폰트 패밀리/크기는 PIU 셀에서 추출해 동일하게 적용.

## 8. 테스트 전략

- **모델 테스트(빠름, Excel 불필요)**: 주어진 params → 블록 리스트가 기대한 구간/행
  수/강조 인덱스/참조 라벨을 갖는지 검증. (<50억 vs ≥50억 분기 핵심 케이스)
- **렌더러 테스트**: 모델 → xlsx 렌더 후, 계산된 좌표의 값·수식·병합 존재·스타일
  (채움/테두리/정렬)을 검증.
- **골든**: <50억 토목 케이스 출력이 PIU `8.적용근거`와 구조적으로 일치(섹션 제목·표
  헤더·행 수·열폭·병합 패턴)하는지 비교. 제비율 원본 파일 없으면 skip(기존 정책 유지).
- **회귀**: 기존 `lookup`/`params` 테스트는 그대로 통과해야 한다.

## 9. 범위 밖 (YAGNI)

- 적용근거 외 다른 시트(산출명세서·내역서·일위대가 등) 생성 — 별도 프로젝트.
- 사용자 정의 디자인 테마/색 변경 UI.
- PDF 출력.

## 10. 마이그레이션/호환

- `build_output()` 공개 시그니처 유지 → `gui.py`/`main.py` 무수정.
- 1차 템플릿 방식 테스트 중 좌표 의존 테스트는 모델/렌더러 테스트로 대체.
- 기본 출력 경로는 현재 작업 디렉토리(`적용근거_결과.xlsx`) — 이미 반영됨.
