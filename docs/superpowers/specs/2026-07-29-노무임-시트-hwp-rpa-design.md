# 노무임 시트(7번) HWP 통합 RPA — 설계

**작성일:** 2026-07-29
**상태:** 승인 대기(스펙 검토 전)
**선행 설계:** `docs/superpowers/specs/2026-06-30-적용근거-코드생성-렌더러-design.md` (8.적용근거 코드 생성)

## 1. 배경과 목표

현재 도구는 제비율 엑셀 + 기본정보 → **`8.적용근거`** 시트를 코드로 그린다(구현 완료).
PIU 실무 제출물은 여기에 **`7.통신노무임`**(시중노무임 산출 근거) 시트가 함께 붙는다.

이 시트의 노임단가 출처는 대한건설협회 **「건설업 임금실태조사 보고서」(.hwp)** 이며,
분기마다 새 파일이 배포된다. 목표는:

> 제비율 엑셀 + **임금실태조사 hwp** + 기본정보를 넣으면
> **한 워크북에 `7.통신노무임`·`8.적용근거` 두 시트**가 자동 생성되는 RPA.

`8.적용근거`는 기구현. **신규 작업은 `7.통신노무임` 시트와 hwp 파싱**이다.

## 2. 대상 산출물 구조 (PIU `7.통신노무임` 분석 결과)

- 제목 1행: "7.2026년도 상반기 시중노무임 산출" (시점은 hwp에서 파생)
- 헤더 2행: `번호 | 직종명 | No.(코드) | 공표일(과거 3시점) | 현재시점 시중노임 | 변동율(%) | 비고`
- 본문: **부문별 그룹**(Ⅰ.일반공사직종 / Ⅱ.광전자직종 / Ⅲ.기타직종 …)으로 묶고,
  각 그룹 끝에 **노임변동률평균** 행.
- 나열되는 직종은 132직종 전체가 아니라 **이 공사에 실제 쓰인 직종만**(PIU는 22직종).

### 검증된 열 구조와 계산 규칙 (전부 파생 — 하드코딩 아님)
hwp "개별직종 노임단가" 표의 노임 열은 **최신이 왼쪽(내림차순)**. 실측 헤더:
```
공 표 일:  2026.1.1  2025.9.1  2025.1.1  2024.9.1
보통인부:   172,068   171,037   169,804   167,081
```
- **현재 노임 = 첫 열(가장 최신, 예 2026.1.1)**
- **변동율 = (현재 − 직전반기) / 직전반기** = `(w[0] − w[1]) / w[1]`
  - 실측: 보통인부 (172,068−171,037)/171,037 = 0.00603
- 시트 7은 hwp 열을 **역순(오래된→최신)** 으로 표시: 공표일 = 과거 3시점, 마지막 = 현재.
- 노임변동률평균 = 부문 그룹 내 각 직종 변동율의 **산술평균**
- 열 개수·날짜는 hwp "공 표 일" 블록에서 파싱(4열 고정 가정 금지 — 읽은 개수대로).

**주의:** PIU 샘플의 "현재"값(보통인부 167,081)은 우리 hwp의 **가장 오래된 열(2024.9.1)** 과
같다 — PIU는 **2024 하반기 보고서**로 작성됐기 때문. 2026 hwp를 넣으면 "2026 상반기" 시트가
나오는 것이 정상 동작이며, 시점·값이 파일에 따라 자동으로 이동한다.

## 3. HWP 파싱 견고성 (분기별 양식 변동 대응)

hwp는 완전 고정 양식이 아니라 분기마다 갱신된다. **위치·인덱스가 아니라 앵커·패턴·검증**
기반으로 파싱한다. 기존 `lookup.py`가 엑셀에서 `[간접노무비]` 앵커를 쓰는 철학과 동일.

| 분기마다 변함 (의존 금지) | 구조적으로 안정 (의존 가능) |
|---|---|
| 노임 값 | HWP 5.x(OLE 복합문서 + `BodyText/Section*` zlib) 포맷 |
| 문단/셀 위치·인덱스 | "개별직종 노임단가" 표가 존재 |
| 직종 개수(127→132→…) | 행 패턴: `4자리 코드 → 직종명 → 노임 숫자 셀들` |
| 노임 열 개수·날짜 | 코드 체계(1xxx 일반공사·2xxx 광전자·3xxx 국가유산·4xxx 원자력·5xxx 기타) |
| 직종 통합/개명 | 직종명 라벨 |

### 파싱 방침 (표 grid 디코드 — 실측 검증 완료)
1. **표 컨트롤 grid 디코드** — `BodyText/Section*`를 HWP 레코드(tag/level/size)로 파싱.
   표 컨트롤(`HWPTAG_CTRL_HEADER` ctrl-id `tbl `) 내부의 각 셀 `HWPTAG_LIST_HEADER`에서
   (row, col)을 읽어 셀 텍스트(`HWPTAG_PARA_TEXT`)를 격자에 배치한다. 순차 문단 펼침 방식은
   코드=숫자/헤더반복/셀 재배열로 취약 → **쓰지 않는다**. (실측: 통신설비공 행
   `['1087','통신설비공','315,528','314,787','308,930','305,050']` 정확 복원.)
2. **노임표 식별 + 페이지 병합** — 노임표는 페이지마다 별도 table 컨트롤로 **분할**된다.
   헤더행(col≥2가 `\d{4}\.\d{1,2}\.\d{1,2}` 날짜) + 데이터행(col0이 `\**\d{4}` 코드)을 가진
   표를 **모두** 찾아 문서 순서로 병합하고, 각 표의 **반복 헤더행은 스킵**한다.
3. **행 파싱** — col0=코드(`*`·`**` 마커 제거), col1=직종명, col2..= 노임(콤마 정수,
   `-`=미조사→None). 열 개수는 헤더 날짜 칸 수로 파생.
4. **열 개수 파생** — 노임 열이 4개든 5개든 읽은 개수대로. **현재=첫 열(최신), 직전=둘째 열**
   (§2 실측: 최신이 왼쪽). 시트 표시는 역순.
5. **직종은 이름으로 매칭** — 선택 직종을 hwp가 가진 이름과 대조. 없으면 경고(0 대입 금지).
6. **부문 분류 = 코드 prefix** — 실측 결과 노임표에는 부문 라벨 행이 없고(헤더는 날짜뿐),
   직종은 코드 순서로 나열된다. 부문은 **코드 prefix(1xxx 일반공사·2xxx 광전자·3xxx 국가유산·
   4xxx 원자력·5xxx 기타)** 로 결정하며, 이는 보고서의 「평균임금현황」 부문 직종수
   (91/3/18/4/16)와 일치하는 **보고서 자체 분류**다. 선택 직종이 있는 부문만 표시한다.
   - 참고: PIU 7번은 화물차운전사(1049)·인력운반공(1045)을 저자 재량으로 III.기타에 넣었으나,
     이는 hwp 분류(1xxx=일반공사)와 다른 개별 편집이다. 본 도구는 **보고서 분류(코드 prefix)를
     따른다**.

### 검증 가드레일 (fail-loud)
파싱 결과가 이상하면 **조용히 틀린 값을 내지 않고 `HwpFormatError`로 멈춘다**:
- 직종 수가 하한 미만(예: < 50), 코드가 4자리 아님
- 노임값이 비정상 범위(예: 3만~200만 밖), 콤마/공백/`-`(미조사)/`*`·`**`(표본부족) 마커 처리 실패
- 앵커("개별직종 노임단가") 미발견

## 4. 아키텍처

기존 렌더러 아키텍처(선언적 블록 → 행 커서 렌더) 패턴을 그대로 확장한다.

| 모듈 | 역할 | 의존 |
|---|---|---|
| `src/hwp_reader.py` (신규) | hwp(OLE+zlib) → `{직종명: NomuRate(code, 부문, wages[], dates[])}` + 보고서 메타(시점/제목). 순수 함수, 파일→데이터 | `olefile`, `zlib` |
| `src/nomu_model.py` (신규) | 선택 직종 + 노임데이터 + 기본정보 → **블록 리스트**(부문 그룹/헤더/직종행/변동률평균). openpyxl 없음, 순수 데이터. **입력이 구조를 결정하는 유일한 곳** | `hwp_reader` |
| `src/renderer.py` (확장) | 노임표용 블록 렌더(그룹헤더·N열 노임·변동율·평균 행) 추가. **워크북/워크시트 하나에 그리도록 리팩터** — 현재 `render(blocks, out_path)`는 Workbook을 새로 만들어 저장하므로, `render_sheet(ws, blocks)`(주어진 시트에 그림) + 얇은 `render(blocks, out_path)` 래퍼로 분리해 다중 시트 지원. 기존 `styles` 재사용 | `openpyxl`, `styles` |
| `src/builder.py` (수정) | 한 워크북에 시트 2개 생성 후 `render_sheet`를 시트별로 호출(7번·8번) | `sheet_model`, `nomu_model`, `renderer` |
| `src/main.py`/UI (수정) | hwp 파일 선택 + 직종 체크리스트(표준세트 프리체크) 추가 | `tkinter`, `hwp_reader` |

### 데이터 흐름
```
제비율.xlsx ─┐
기본정보   ──┼→ compute_rates → sheet_model.build → blocks8 ─┐
             │                                               ├→ renderer(2 시트) → xlsx
임금실태.hwp ┴→ hwp_reader → 후보직종 ─(체크)→ nomu_model.build → blocks7 ─┘
                                          ↑
                              기본정보(공사명·시점)
```

## 5. 노무임 레이아웃 모델 (신규 블록 타입)

순수 데이터. 좌표 없음, 순서만. 렌더러가 행 커서로 좌표 부여(기존과 동일 철학).

- `NomuTitle(text)` — "7.2026년도 상반기 시중노무임 산출".
- `NomuHeader(past_cols[], current_col)` — hwp 열을 역순(오래된→최신)으로 정렬한 과거 시점
  라벨들 + 현재 시점 라벨. hwp "공 표 일" 블록에서 파생.
- `NomuGroup(roman, name)` — "Ⅰ. 일반공사직종" 등 부문 그룹 헤더.
- `NomuRow(no, name, code, wages[], delta)` — 직종 1행. `wages`는 열 개수 가변, `delta`=변동율.
- `NomuAvg(value)` — 그룹 노임변동률평균 행.

블록 개수·그룹 구성이 **선택 직종에 따라** 달라지는 것이 자동 생성의 본질.

## 6. 직종 선택 (기본정보의 핵심)

- hwp에서 읽은 전 직종을 tkinter **체크리스트**로 표시(직종명·부문·현재노임 미리보기).
- **통신공사 표준세트**를 프리체크(PIU 실사용 직종을 기본값 상수로 보유):
  통신설비공·통신내선공·통신케이블공·통신외선공·보통인부·특별인부·계장공·내선전공·
  고압/저압케이블전공·송전전공·배전전공·플랜트전공·비계공·배관공·무선안테나공·
  기계설비공·지적기사·지적산업기사·지적기능사·H/W시험사·S/W시험사·광케이블설치사·
  통신관련기사/산업기사/기능사·전기공사기사·화물차운전사·인력운반공.
- 사용자가 가감 → 확정. 표준세트는 **기본값일 뿐 하드코딩 강제 아님**(전 직종 목록은 hwp에서 옴).

## 7. 스타일 충실도

PIU `7.통신노무임`에서 추출해 기존 `styles.py`에 상수 추가:
- 헤더 채움/가운데 정렬/굵게(기존 `header_fill` 재사용).
- 노임 셀: 천단위 콤마 숫자 서식, 변동율 셀: 백분율(소수 1~2자리).
- 부문 그룹 헤더: 굵게(로마숫자 라벨).
- 노임변동률평균 행: 강조 또는 굵게.
- 병합: 헤더 `공표일`(과거 시점 묶음), 제목 행. 실제 행 위치 기준 재계산(고정 좌표 아님).

## 10. 마이그레이션/호환

- `build_output()` 시그니처는 hwp 경로·선택 직종을 **선택 인자**로 확장(기존 호출 호환:
  인자 없으면 8.적용근거 단일 시트만 생성).
- 기본 출력 경로는 현재 작업 디렉토리 유지.
- `*.hwp`는 대용량/입력 파일이므로 `.gitignore`에 추가.
